### CL-1｜convTranspose2d 显式 padding ★首推
- **问题**：`// TODO(crbug.com/493652470): Support explicit padding for transpose conv2d.`（`:421`）。TFLite `TransposeConv` 仅支持 SAME/VALID 隐式 padding，显式 output padding 目前直接 `base::unexpected`。
- **文件**：`services/webnn/tflite/graph_builder_tflite.cc:421`（`CalculateExplicitPadding`/`SerializeConvTranspose2d` 路径）。
- **工作量**：小-中。可用显式 `Pad` op 组合模拟，且已有近期 `explicit padding` 类改动可参照。
- **价值**：convTranspose 是分割/生成类视觉模型关键算子，缺显式 padding 会让整条模型走不通 WebNN。边界清晰、纯 emulation、风险最低，**适合建立提交节奏的第一枪**。

### CL-2｜convTranspose2d dilations + groups
- **问题**：`// TODO(crbug.com/364348906): Support dilations and groups parameter for convTranspose2d`（`:4561`）。当前 `dilations!=1 || groups!=1` 直接 `base::unexpected("convTranspose2d doesn't support dilations and groups.")`（`:4574`）。
- **文件**：`graph_builder_tflite.cc:4561`。
- **工作量**：中（dilation 可借 TFLite 参数，groups 需拆分多次卷积组合）。
- **价值**：补齐 convTranspose 参数完整度，与 CL-1 同区域，可连续产出。

- **工作量**：中。
- **价值**：pooling 显式 padding 在检测/分类模型常见，补齐减少 fallback。

## 任务二：WebNN 创新点（跨技术栈，结合三条工作主线）

| # | 创新方向 | 所属层 | 可行性 |
|---|----------|--------|--------|
| 创新-1 ★ | LiteRT NPU accelerator 接线 → OpenVINO delegate 落地 | Runtime/Backend(NPU) | 高 |
| 创新-2 | mmap 跨进程 weights 共享（接续 quota） | 架构/内存/沙箱 | 中 |
| 创新-3 | MLTensor↔WebGPU 零拷贝互操作 | 架构+Backend | 中-高 |
| 创新-4 | OpenVINO CiP AOT 编译缓存降 NPU TTFT | Backend(NPU)+系统 | 中 |
| 创新-5 | 动态 shape + KV-cache 内存治理使能 in-browser SLM | Framework+spec+架构 | 中-难 |

### 创新-1｜LiteRT NPU accelerator 接线，铺路 OpenVINO delegate ★与你工作最契合
- **所属层**：Runtime/Backend（LiteRT ↔ OpenVINO/Intel NPU）。
- **活代码证据**：`graph_impl_litert.cc:401 // TODO(crbug.com/454732289): Support NPU accelerator.` + `:192` 因 LiteRT 暂无查询 runtime accelerator 的 API 而从 compilation options 反推设备的 workaround。
- **生态**：LiteRT 的 Intel NPU（OpenVINO）delegate 已成型——compiler plugin + dispatch plugin，子图 AOT 编译成 `DISPATCH_OP`；OpenVINO **2026.1 起 Compiler-in-Plugin 为默认 NPU 编译器**（端侧编译、免 OEM 驱动更新，需 NPU driver v1.32.1）。你的 PDF 方案正是这条链路在浏览器内的落地。
- **技术价值**：WebNN 相对 WebGPU 的**核心差异化**——WebGPU 够不到 NPU。
- **成长价值**：贯通 Web 平台→LiteRT→delegate→OpenVINO→Level Zero 全栈 + 跨进程/沙箱/二进制体积取舍。
- **可行性**：高。先做小块——把 `:192` 的 accelerator 查询/推断独立成 CL，为 delegate 接入铺前置基础设施。

### 创新-2｜mmap 跨进程 weights 共享（直接延续你的 quota 设计）
- **所属层**：架构/内存/沙箱。
- **证据**：git 最新提交 `89a89c752b validate disk space before creating weights files` 就是 quota 主线；`context_impl_litert.cc:189 // TODO(crbug.com/332350952): implement constant tensors for LiteRt.` 常量张量尚未实现，为权重共享留了口子。
- **技术价值**：renderer 持 writable fd 的 capacity tracker 之上，用 mmap 让 GPU/renderer 进程零拷贝共享权重，同时压低构建期内存峰值（对标上游 #901 hollow constants 动机）。
- **成长价值**：把内部 quota 实现升级为可反哺上游 spec 的原创叙事。
- **可行性**：中。建议先写设计 doc 接续 `weights-file-quota-impl-guide.md`，再落 capacity tracker CL。

### 创新-3｜MLTensor ↔ WebGPU 零拷贝互操作
- **所属层**：架构 + Backend。
- **生态**：**WebML WG 2026-06-18 已正式决议**把 MLTensor↔WebGPU interop 从 explainer 移入 WebNN 正式 spec（`exportToGPU()` 把 `MLTensor` 暴露为 `GPUBuffer`）；hardware buffer 支持 macOS 最成熟，Windows/Linux 正基于 LiteRT 实现中。
- **技术价值**：解锁"WebNN 推理 + WebGPU 渲染/后处理"零拷贝管线（实时视频 ML 刚需）。
- **成长价值**：正值 spec 定型窗口期，Linux/LiteRT 侧实现是能同时在 Chromium 与 W3C 留影响力的方向。
- **可行性**：中-高（spec 刚决议、平台实现进行中，正好切入）。

### 创新-4｜OpenVINO CiP AOT 编译缓存，降 NPU 冷启动 TTFT
- **所属层**：Backend(NPU) + 系统。
- **技术价值**：WebNN 正设计开发者显式控制的编译缓存 API；OpenVINO 有 `ov_compiled_model_export_model`/`import_model`，NPU（尤其 CiP）编译开销大，缓存收益显著。把两者打通可大幅降交互式 Web 应用的 NPU 冷启动延迟。
- **成长价值**：横跨 spec API 设计 + 后端编译产物序列化 + 跨会话缓存隐私边界。
- **可行性**：中。可先在 OpenVINO delegate 内部做 export/import 缓存原型验证收益。

### 创新-5｜动态 shape + KV-cache 内存治理，使能 in-browser SLM（跨层）
- **所属层**：Framework + spec + 架构。
- **技术价值**：动态形状是浏览器内 LLM 头号阻塞（KV cache 序列维天然动态，ORT WebNN EP 目前拒绝无 `dim_value` 输入而回退 WASM）。结合你的 quota/capacity tracker 做 KV-cache 动态扩展，是 WebNN 相对 WebGPU 手写 attention 的差异化能力；配合 Gemm int4（`:2271`）打通 4-bit 小 LLM。
- **成长价值**：把量化、LLM 推理、spec 算子设计三者串起来，覆盖面最广、最前沿。
- **可行性**：中-难。渐进第一步：有界固定尺寸图自动实例化 + LRU 缓存，避开一次性重构 compute-stage shape inference。
