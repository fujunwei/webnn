### CL-1｜Conv2D 激活融合 ★
- **问题**：`// TODO(crbug.com/344633746): Consider fusing Conv2D activations when ...`（`:4939`）。Conv2D 后接激活未融合，多一次 kernel 往返。
- **文件**：`tflite/graph_builder_tflite.cc:4939`。
- **工作量**：中。
- **价值**：**性能向 CL**（区别于纯 coverage），CNN 类模型普遍受益；LiteRT 默认开启后直接改善线上推理延迟。

### CL-2｜量化 Gemm 融合 ★
- **问题**：`// TODO(crbug.com/372932099): Fuse quantized gemm when gemm.alpha or gemm.beta ...`（`:2254`）。带 alpha/beta 的量化 Gemm 未融合。
- **文件**：`:2254`。工作量：中。
- **价值**：贴合你熟悉的量化/QDQ 融合线，transformer 类模型的 matmul 热点，性能收益明确。

### CL-3｜Gemm b-operand int4 量化
- **问题**：`// TODO(crbug.com/425746878): Support int4 quantization for b operand.`（`:2271`）。
- **价值**：4-bit 权重是端侧 LLM 关键；与你量化线契合，是打通小 LLM 的前置。

### CL-4｜GPU 内存消耗优化
- **问题**：`// TODO(crbug.com/359729258): Save GPU memory consumption.`（`:9731`）。
- **价值**：**内存向**，直接呼应你的 weights/内存主线；GPU 内存是端侧大模型瓶颈。可与 quota/capacity tracker 叙事联动。

### CL-5｜float16 直连，免 dequantize
- **问题**：`// TODO(crbug.com/369649350): Support float16 without dequantize operator.`（`:4476`）。当前 float16 需插入 dequantize，多余开销。
- **工作量**：小-中，机械补全 + 性能收益，易过审。

**备选**：elu alpha custom op（`:970`/328736354，偏大）、skip identity 实现（`:7386`/336399247）、large tensor 上限（`:6023`/499018899，安全向）、constant input after TFLite runtime fix（`:8607`/375614289）。

## 任务二：WebNN 创新点（跨栈，结合三条主线）

| # | 创新方向 | 所属层 | 可行性 |
|---|----------|--------|--------|
| 创新-1 ★ | LiteRT 算子融合框架化（把散点 fusion TODO 系统化） | Runtime/性能 | 中-高 |
| 创新-2 ★ | mmap 跨进程 weights 共享 + GPU 内存优化联动 | 架构/内存 | 高 |
| 创新-3 | LiteRT NPU accelerator 接线 → OpenVINO delegate | Backend(NPU) | 高 |
| 创新-4 | int4 块量化端到端打通小 LLM（LiteRT 路径） | Models+量化 | 中-难 |

### 创新-1｜LiteRT 算子融合框架化 ★（今日新角度）
- **所属层**：Runtime / 性能。
- **动机**：活代码里 fusion 相关 TODO 散落多处（Conv2D 激活 `:4939`、量化 Gemm `:2254`，及 `413083273` 系列 GPU delegate 限制）。与其逐个补，不如设计一个**统一的融合 pass / pattern 匹配层**，把这些 fusion 规则收敛。
- **技术价值**：从"点状修 TODO"升级为"系统性性能基础设施"，LiteRT 默认开启后收益放大。
- **成长价值**：图优化/pattern rewrite 是编译器核心能力，履历含金量高。
- **可行性**：中-高。可先做 Conv+activation 一个 pattern 起步（即 CL-1），再抽象成框架。

### 创新-2｜mmap 跨进程 weights 共享 + GPU 内存优化联动 ★
- **所属层**：架构/内存/沙箱。
- **证据**：`:9731 Save GPU memory consumption` + `9cd6ca3452 Eliminate MemoryMappedFile::data()` + 你的 quota 主线 `e8962bc66f`。三者都指向内存所有权重构窗口。
- **技术价值**：capacity tracker 之上用 mmap 零拷贝共享权重，同时把 GPU 内存优化(CL-4)纳入统一内存治理。
- **可行性**：高。建议写设计 doc 接续 `weights-file-quota-impl-guide.md`。

### 创新-3｜LiteRT NPU accelerator 接线 → OpenVINO delegate
- **所属层**：Backend(NPU)。证据：`graph_impl_litert.cc:401`（454732289）NPU accelerator 待接线 + `:192` workaround 仍在。
- **价值**：你 OpenVINO PDF 方案的自然前置；WebNN 相对 WebGPU 的核心差异化。可行性高，先做 accelerator 查询/推断小 CL。

### 创新-4｜int4 块量化端到端打通小 LLM（LiteRT 路径）
- **所属层**：Models + 量化。
- **技术价值**：CL-3(int4 b-operand) + CL-2(量化 Gemm 融合)铺路后，验证一个 4-bit 小 LLM 在 LiteRT 路径端到端跑通，是差异化能力。
- **可行性**：中-难。可交付子目标：单个小模型端到端 + 性能基线。
