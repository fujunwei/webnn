### 创新-1｜借 `MemoryMappedFile` 清理东风，推进 mmap 跨进程 weights 共享 ★与你工作最契合
- **所属层**：架构/内存/沙箱。
- **新信号**：`9cd6ca3452 Eliminate base::MemoryMappedFile::data() and length() usage` 表明 services 层正在收敛内存映射的直接用法——这正是重新设计 weights 内存所有权/共享语义的窗口期。叠加 `context_impl_litert.cc:188` 常量张量尚未实现（332350952）与你 quota 主线的 `e8962bc66f validate disk space`。
- **技术价值**：在 capacity tracker 之上用 mmap 让 GPU/renderer 零拷贝共享权重，压低构建期内存峰值。
- **成长价值**：把内部 quota 实现升级为可反哺上游的架构叙事，恰逢内存映射重构窗口，切入成本低。
- **可行性**：高。建议先写设计 doc 接续 `weights-file-quota-impl-guide.md`，与正在进行的 MemoryMappedFile 清理对齐接口。

### 创新-2｜LiteRT NPU accelerator 接线，铺路 OpenVINO delegate
- **所属层**：Runtime/Backend（NPU）。
- **活代码证据**：`graph_impl_litert.cc:401 // TODO(454732289): Support NPU accelerator.` + `:192` 因 LiteRT 无 accelerator 查询 API 而反推设备的 workaround（仍在）。
- **技术价值**：WebNN 相对 WebGPU 的核心差异化——够得到 NPU；你的 OpenVINO PDF 方案的自然前置。
- **可行性**：高。先把 `:192` 的 accelerator 查询/推断独立成 CL。

### 创新-3｜跟进 `mojom::WebNNGraph` 移除后的图构建/校验重构
- **所属层**：架构。
- **新信号**：`df9c42bb3d Remove mojom::WebNNGraph interface`——图 IPC 接口刚被移除/重构，周边校验、序列化、错误传播路径会有连带清理与潜在 bug。
- **技术价值/成长价值**：紧跟主线重构能顺势捡到高价值 follow-up CL，并深入理解 WebNN 的 mojo/IPC 架构。
- **可行性**：中-高。建议 `git show df9c42bb3d` 摸清改动面，找未清理干净的调用点。

### 创新-4｜LiteRT 默认开启后的算子覆盖度量 + 回归基线
- **所属层**：系统 + 测试。
- **动机**：`3d30b11269` 默认开启后，"哪些真实模型/算子在 LiteRT 路径 fallback"成了运营关键问题。建一个覆盖度量/回归基线工具，能系统性发现 CL 机会（把任务一从"grep TODO"升级为"数据驱动选题"）。
- **可行性**：中。可从跑一批代表性模型统计 `base::unexpected`/fallback 命中入手。

### 创新-5｜动态 shape + KV-cache 内存治理，使能 in-browser SLM（跨层）
- **所属层**：Framework + spec + 架构。
- **技术价值**：动态形状是浏览器内 LLM 头号阻塞；结合你的 quota/capacity tracker 做 KV-cache 动态扩展，配合 int4 块量化（CL-2/CL-4 铺路）打通 4-bit 小 LLM。
- **可行性**：中-难。渐进第一步：有界固定尺寸图自动实例化 + LRU 缓存。
